# Deploying to Render

The site used to be a Render **Static Site**. It's now a Node server
(Express + Neon Postgres), so it needs a **Web Service**. The old static
site keeps running untouched until the domain is moved over.

Secrets are deliberately not in this file — the repo is public.

---

## 1. Create the database (Neon)

1. [console.neon.tech](https://console.neon.tech) → **New Project** → name it
   `qm-lawncare`, region **AWS US East (Ohio)** (same as Render).
2. Dashboard → **Connect** → turn on **Connection pooling** → copy the
   connection string. That's `DATABASE_URL`.

Nothing else. The tables are created and the 18 original gallery photos are
imported on the first boot.

## 2. Create the service

1. [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**
2. Connect `Jedcooper123/qm-lawncare`, branch `main` (once `full-stack` is
   merged — or pick `full-stack` to try it first).
3. Render reads [`render.yaml`](render.yaml): one web service, **Starter
   ($7/month)**, same as Classic Cleanz. The free plan sleeps after 15 idle
   minutes and makes the next visitor wait ~50 seconds.

## 3. Environment variables

| Variable | Value |
|---|---|
| `DATABASE_URL` | Neon pooled connection string (step 1) |
| `OWNER_PASSWORD` | Quinlan's portal password. **Minimum 10 characters.** Re-applied on every restart, so it's also how you reset a forgotten password |
| `OWNER_EMAIL` | `quinlanmarsh05@gmail.com` (preset by render.yaml) |
| `OWNER_NAME` | `Quinlan Marsh` (preset) |
| `SESSION_SECRET` | Generated by Render automatically |
| `SITE_URL` | The real domain once it's moved, e.g. `https://www.example.com` |

Deploy, then check the logs for `[db] imported 18 photos` and `[db] ready`.

## 4. Check it on the .onrender.com URL

- Homepage gallery shows all 18 photos and the filters work
- `/admin` → sign in → upload a photo → it appears on the homepage
- Delete that test photo

## 5. Move the domain

1. Old **static site** → Settings → Custom Domains → remove the domain.
2. New **web service** → Settings → Custom Domains → add the same domain.
   Render shows the DNS records; if they're the same as before nothing
   changes at the registrar, otherwise update them there.
3. Set `SITE_URL` to the domain.
4. Once the domain serves the new site with HTTPS, suspend or delete the
   old static site.

## How it works

- **Photos live in Neon**, because Render's disk is wiped on every deploy.
  Each upload is resized to max 1400px (~300 KB) with GPS/location data
  stripped. Neon's free 0.5 GB holds well over a thousand.
- **Neon stays asleep** when nobody's editing: the server keeps the photo
  list and image bytes in memory, photo URLs are cached by browsers for a
  year, and `/healthz` never touches the database (the Classic Cleanz
  outage in Sept 2026 was a health check keeping Neon awake).
- **Website Photos** (banner, About photos, logo) can be replaced from
  /admin. They're stored in the `site_images` table; deleting a row puts
  the original from `public/` back. In the HTML they're
  `__SITE_IMAGE_<key>__` placeholders, filled in by the server.
- **If Neon is down**, the site still serves, using the 18 launch photos
  from `seed/photos/`, and keeps retrying every 2 minutes.
- The schedule and contact forms still go through formsubmit.co to
  quinlanmarsh05@gmail.com, unchanged.
